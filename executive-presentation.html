Stage 1 of 3

Install OSV-Scanner v2.3.8.

Prebuilt Linux/amd64 binary fetched from GitHub Releases, placed on PATH. Go-build and apt paths are valid alternatives that this run did not require.

Path chosen

  • Prebuilt binary (~58 MB)
  • Verified by osv-scanner --version
  • Reports version: 2.3.8
  • Backward-compatible JSON contract (V2 line)

Alternatives considered

  • go install requires Go 1.26.2+ (not installed)
  • apt install osv-scanner not in Ubuntu 25.10 repos
  • Offline DB (--experimental-local-db-path) skipped — network OK
  • Pin: v2.3.8 (latest in V2 line at run time)

Mitigations.

What this configuration controls and what it knowingly defers.

Risk & mitigation

Known limits, deliberate choices.

Controlled

  • Scanner version pinned (v2.3.8)
  • Output schema deterministic and validated
  • UTF-8 safe truncation by Unicode code-points
  • CVSS computed by canonical library

Deferred (by design)

  • No package upgrades or remediation
  • No CI/CD wiring (not requested)
  • 26 records lack a CVSS vector → bucketed low
  • Cross-config dedup owned by aggregator

Section 5 of 6

Team onboarding.

Reproduce this run in three commands, on any Linux host with curl + Python 3.10+.

Run it yourself

Three commands — the whole pipeline.

Prerequisites

  • Linux/amd64 host
  • Python 3.10–3.13
  • Network access to OSV.dev
  • pip install --break-system-packages cvss

Commands

  • curl … > /usr/local/bin/osv-scanner && chmod +x …
  • osv-scanner scan source --recursive --format json --output results-osv.json <repo>
  • python3 normalize_findings.py <repo> results-osv.json findings-config-f.json
  • cat findings-config-f.json | wc -l → 1
