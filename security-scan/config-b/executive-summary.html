How it works

Pipeline

Scan pipeline lifecycle

sequenceDiagram
  autonumber
  participant O as Operator
  participant S as run-scan.sh
  participant SG as Semgrep CE
  participant N as normalize-findings.py
  O->>S: ./run-scan.sh
  S->>S: Create .venv & install Semgrep 1.163.0
  S->>SG: Download p/security-audit, p/secrets, p/owasp
  S->>SG: --metrics=off --config=rule-cache --dry-run
  SG-->>S: Exit 0 (offline gate passed)
  S->>SG: Main scan emits SARIF
  SG-->>S: results-semgrep.sarif
  S->>N: normalize-findings.py
  N-->>S: findings-config-b.json
  S-->>O: Pass/fail gates + scan-metadata.json

Risks & limitations

Known limits

Known limitations (transparent disclosure)

Limit Explanation
Semgrep CE vs Pro Framework-specific Pro rules not exercised; CE scope is the engine + community packs
CWE-Unknown fallback Used only when rule metadata omits CWE and no keyword inference matches
Default targeting Verbatim user command — no --include / --exclude filters added
No remediation Config B is scan-and-report; triage / fix is downstream

Operational readiness

Verification

Pass/fail gates (every gate verified by the harness)

Gate Verification
Offline operation Semgrep dry-run exits 0 with no network
SARIF valid runs array present
Single line wc -l == 1 (no embedded newlines in JSON)
Valid JSON python -m json.tool exits 0
Five fields Every record has {file, line, severity, cwe, description}
Description bound len(description) ≤ 200
