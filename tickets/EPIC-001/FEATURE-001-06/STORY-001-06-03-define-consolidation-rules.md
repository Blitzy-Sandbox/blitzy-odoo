This is the third story of the `FEATURE-001-06/` folder and the one that turns the configured group into a **stated policy**: the rule set a consolidation run reads before it touches a single balance. It carries four rule classes in one rule set — the **consolidation scope and method** per entity, the **mapping** of each entity's local chart onto the group taxonomy, the **translation policy** that names which rate class translates which class of balance and on which rate date, and the **elimination-rule registry** that names each pair of group accounts to be removed together with the journal the resulting entry posts through. The rules are **defined** here and **executed** elsewhere: [STORY-001-06-04](./STORY-001-06-04-eliminate-intercompany-balances.md) posts the elimination entries and [STORY-001-06-05](./STORY-001-06-05-generate-consolidated-financials.md) renders the consolidated statements, both reading this rule set rather than restating it. Ordering rule **ORD-003** in the Epic places [STORY-001-06-01](./STORY-001-06-01-configure-company-hierarchy.md) ahead of this story, because a rule has no entity chart to map and no rate to select until the three companies, their functional currencies and the group presentation currency exist. It does **not** depend on [STORY-001-06-02](./STORY-001-06-02-post-intercompany-transactions.md): a mapping is defined against accounts, not against postings. Every entity name, functional currency, ownership percentage and rate below is consumed unchanged from the Epic's canonical legal-entity register ([Appendix E.4](../../EPIC-001-enterprise-accounting-odoo.md#e4-canonical-legal-entity-register)) and its canonical group chart of accounts ([Appendix E.2](../../EPIC-001-enterprise-accounting-odoo.md#e2-canonical-group-chart-of-accounts)); this story defines no entity and no account code of its own.

## User Story

**As a** Group Controller

**I want** one governed consolidation rule set that names the entities inside the group's consolidation scope with the method applied to each, maps every in-scope account of Global Europe SARL's and Global Asia Pte Ltd's local charts onto exactly one node of the group taxonomy, states which rate class translates which class of balance and on which rate date, and registers each elimination pair together with the journal the entry it generates posts through

**So that** each consolidation run reproduces the group position from stated configuration instead of from a workbook — Global Europe SARL's total assets of `€850,000.00 EUR` reaching the group presentation currency as `$922,250.00 USD` at the 2025-03-31 closing rate of 1.0850 USD/EUR, rounded to 2 decimal places at the USD rounding increment of 0.01, with the translation residual of `$1,230.00 USD` presented in Currency Translation Adjustment 3200 rather than absorbed into Retained Earnings 3100 — and the consolidated Balance Sheet and Profit & Loss are published within 48 hours of the last entity close (SM-013), with every intercompany pair carrying a registered elimination rule so no balance survives into the group position by omission (SM-012).

## Acceptance Criteria

Seven criteria are authored, inside the 4-to-8 bound the Epic sets for a story, and they carry the mandated coverage distribution: **Scenarios 1, 2, 3 and 4** are the valid-input cases, one per rule class (scope and method, translation policy, account mapping, elimination registry); **Scenario 5** is the invalid and incomplete-input case; **Scenario 6** is the error-handling case; and **Scenario 7** is the accounting edge case, where an entity enters the group part-way through the fiscal year.

Every criterion that spans entities names the affected company. Every account is cited by its code from the Epic's canonical chart, every monetary figure states its currency, its amount and its rounding, and every translated figure also states the rate class, the rate and the rate date it was translated at, so no figure below is a bare conversion. Rounding is half-up to the decimal places implied by each currency's rounding increment, read from the currency record rather than assumed: 2 decimal places at the increment of 0.01 for USD, EUR and SGD.

**Where the hostile-input cases sit.** The Epic writes a story's invalid-input and error-handling criteria as hostile-input cases where the story itself ingests an external response. This story **resolves** rates that are already stored and already validated: ingestion of the exchange-rate feed, with the parsing, transport, authenticity, freshness and replay controls C-015 through C-022 and CWE-345 require, is configured by [STORY-001-06-01](./STORY-001-06-01-configure-company-hierarchy.md). C-022 nonetheless names this story as one of the two that must carry a test per hostile case on that path — a malformed response, a schema-invalid response, an external-entity payload, an oversized response, a disallowed content type and an out-of-range rate value — so those cases are carried as named acceptance tests in § Test Requirements, alongside the assertion that a rejected response produces no translated balance and leaves the last confirmed rate in force. Scenario 5 and Scenario 6 below carry the invalid-input and error-handling coverage for the rule set itself, which is the artifact this story delivers.

### The rule set this story defines

The rule set is one artifact with four rule classes. It is stated here in full so that each criterion asserts a part of a policy that is written down, rather than a preference expressed at run time.

**Rule 1 — consolidation scope and method.** Drawn from the Epic's canonical legal-entity register and restated in no other words:

| Entity | Entity code | Functional currency | Ownership held by Global Holdings Inc. | Method | Non-controlling interest arising | In the consolidation scope at 2025-03-31 |
|---|---|---|---|---|---|---|
| Global Holdings Inc. | `US-01` | USD, also the group presentation currency | — | Reporting parent, consolidating entity | — | Yes |
| Global Europe SARL | `NL-01` | EUR | 100.00% | Full consolidation | 0.00% | Yes, from 2019-01-01 |
| Global Asia Pte Ltd | `SG-01` | SGD | 100.00% | Full consolidation | 0.00% | Yes, from 2021-01-01 |
| Global UK Ltd | `GB-01` | GBP | 100.00% | Full consolidation | 0.00% | No — incorporated 2025-04-01, consolidated from the quarter beginning 2025-04-01 |

Both subsidiaries are wholly owned, so the rule set measures **no** non-controlling interest and recognizes **no** goodwill: each subsidiary was incorporated by the parent at subscription value, which is why the investment elimination of Rule 4 is the subscribed capital and nothing else (IFRS 10, ASC 810). Non-controlling-interest allocation and equity-method accounting sit outside the Epic's scope ([§8.1](../../EPIC-001-enterprise-accounting-odoo.md#81-explicitly-excluded-items)), and § Constraints records what the rule set would require of the group chart before a partly owned entity could be admitted.

**Rule 2 — account mapping onto the group taxonomy.** Each in-scope account of each entity's local chart resolves to exactly one node of the group taxonomy released by [STORY-001-01-02](../FEATURE-001-01/STORY-001-01-02-map-accounts-ifrs-gaap-taxonomy.md), which carries one IFRS (IAS 1) presentation line and one US GAAP (ASC 210/220) presentation line per code. The mapping this rule set holds for the codes the group consolidates:

| Local intercompany payable of Global Europe SARL and of Global Asia Pte Ltd | Intercompany Payable 2100 | Trade and other payables | Closing |
| Local investment in a subsidiary held by Global Holdings Inc. | Investment in Subsidiary 1700 | Investments in subsidiaries — caption claimed from STORY-001-01-02 | Historical |
| Local share capital of Global Europe SARL and of Global Asia Pte Ltd | Share Capital 3000 | Issued capital | Historical |
| Local retained earnings of Global Europe SARL and of Global Asia Pte Ltd | Retained Earnings 3100 | Retained earnings | Carried forward for the opening balance, average for the period result |

| Local exchange difference on a monetary balance | Foreign Exchange Gain/Loss 7200 | Other income and expenses — caption claimed from STORY-001-01-02 | Average |

Three facts make the mapping verifiable. Every in-scope account resolves to **exactly one** group node, so a balance cannot reach two group lines or none. Every group code cited above is a row of the Epic's canonical chart and is allocated to FEATURE-001-06 by the [FEATURE-001-01 §7.4 Group Chart-of-Accounts Extension Registry](../FEATURE-001-01-chart-of-accounts-fiscal-year.md#74-group-chart-of-accounts-extension-registry) or belongs to that feature's baseline, so this story **introduces no account code**. And the three presentation captions the STORY-001-01-02 matrix does not yet carry — for Investment in Subsidiary 1700, Currency Translation Adjustment 3200 and Foreign Exchange Gain/Loss 7200 — are **claimed from the owner of the taxonomy in the same change**, never minted inside this rule set; no criterion below asserts a caption that has not been released, which is why Scenario 3 asserts the two captions that exist.

**Rule 3 — translation policy (IAS 21, ASC 830).** One rate class per class of balance, each with the rate date it is drawn from:

| Class of balance | Rate class | Rate date basis | Global Europe SARL | Global Asia Pte Ltd |
|---|---|---|---|---|
| Assets and liabilities | Closing | The reporting as-of date | 1.0850 USD/EUR as of 2025-03-31 | 0.7450 USD/SGD as of 2025-03-31 |
| Income and expense with third parties | Average | The reporting date range | 1.0720 USD/EUR for 2025-01-01 to 2025-03-31 | 0.7380 USD/SGD for 2025-01-01 to 2025-03-31 |
| Equity subscribed at incorporation | Historical | The entity's incorporation date | 1.1000 USD/EUR as of 2019-01-01 | 0.7300 USD/SGD as of 2021-01-01 |
| Opening retained earnings | Carried forward, not retranslated | The prior reporting date, at the amount already presented | `$421,200.00 USD` carried from `€390,000.00 EUR` | `$306,600.00 USD` carried from `S$420,000.00 SGD` |
| Intercompany income and expense between two group companies | The rate the charge was recorded at in the buying entity's books | The transaction date of the charge | 1.0850 USD/EUR as of 2025-03-31 | Not applicable in the worked quarter |
| Translation residual | Not translated — the arithmetic difference | — | Presented in Currency Translation Adjustment 3200 | Presented in Currency Translation Adjustment 3200 |

Four clauses of the policy are stated because each of them decides an amount. **A rate is selected by rate class and rate date, never by date alone**, since three EUR classes are readable for 2025-03-31 and selecting on date alone would return one of them arbitrarily. **Opening retained earnings are carried at the USD amount the prior period's translated statements already presented** and are not retranslated at the current closing rate, so a period already published stays reproducible. **An intercompany income or expense line is translated at the rate its charge was recorded at** rather than at the quarter average rate, so the trading elimination of Rule 4 removes equal amounts from Revenue 4000 and Expense 6100 and leaves no translation residual behind in group profit. And **the residual belongs to Currency Translation Adjustment 3200 alone**: the retranslation of a monetary balance — an intercompany payable held in a currency other than the holder's functional currency — is a different event and is taken to Foreign Exchange Gain/Loss 7200 in the entity's own books, which is why `€37,037.04 EUR` recorded at the 2025-03-15 transaction rate of 1.0800 USD/EUR and retranslated to `€36,866.36 EUR` at the 2025-03-31 closing rate of 1.0850 USD/EUR moves `€170.68 EUR`, rounded to 2 decimal places at the EUR rounding increment of 0.01, through account 7200 and not through account 3200.

## Edge Cases

| # | Edge Case | Expected Handling |
|---|-----------|-------------------|
| 1 | **Zero or null value in a rule input** — an ownership percentage of 0.00% is recorded against an entity declared a consolidated subsidiary, or the rate record the policy resolves for a rate class carries a null or non-positive value | Both are refused with a validation message naming the input at fault and the company it belongs to: an ownership percentage of 0.00% states that the parent holds nothing, which contradicts the declaration of the entity as a consolidated subsidiary, and a rate of null or of 0.0000 translates every balance to `$0.00 USD`, which the platform's own `CHECK (rate>0)` constraint on the rate table already refuses at the record level. No rule set is stored from the refused save, so the scope stays at 2 consolidated subsidiaries at 100.00% each and the group Currency Translation Adjustment 3200 as of 2025-03-31 stays at `$11,090.00 USD`, rounded to 2 decimal places at the USD rounding increment of 0.01. An entity that is in the group but excluded from a period's consolidation is expressed by its consolidation-from date, not by an ownership percentage of 0.00% |
| 2 | **Rule-set change after the period is locked** — a mapping, a rate class or an elimination pair is amended after 2025-03-31, whose journal-entry lock date is set under the closing controls of [STORY-001-01-05](../FEATURE-001-01/STORY-001-01-05-configure-period-lock-dates.md) and whose consolidated pack has been issued | The amendment is stored as a **new version of the rule set effective from a date after the lock date** and does not restate the locked period: the version that produced the issued pack stays in force for 2025-03-31, so re-running the translation for that as-of date still reports Global Europe SARL at `$922,250.00 USD` total assets with a Currency Translation Adjustment 3200 residual of `$1,230.00 USD` and Global Asia Pte Ltd at `$894,000.00 USD` with `$9,860.00 USD`, each rounded to 2 decimal places at the USD rounding increment of 0.01. An amendment offered with an effective date on or before the lock date is refused with a message naming the lock date of 2025-03-31 and the affected companies, and where the group has to restate a locked period it does so through the recorded lock-exception path with the Group Controller's approval, never by editing the version already issued |
| 3 | **Multi-currency rounding across a rate of higher precision than the presentation** — a rate record carries up to 6 decimal places, since the rounding factor on the currency model is stored at `digits=(12, 6)`, while the group presentation currency USD carries a rounding increment of 0.01 and therefore 2 decimal places | The translated amount is rounded **once**, at the presentation currency's increment, after the rate of full stored precision has been applied to the balance being translated — never by rounding the rate first and never by rounding each contributing line and then summing, which would accumulate a difference across a chart of hundreds of accounts. The residual that arises between a rounded total and the sum of its rounded parts is presented in Currency Translation Adjustment 3200 and is bounded by the `$0.02 USD` tolerance SM-012 states for an intercompany pair; the reconciliation still closes at a difference of `0.00 USD` between translated net assets and translated equity components plus the residual |
| 4 | **Entity enters or leaves the group part-way through the fiscal year** — Global UK Ltd is incorporated on 2025-04-01 inside FY2025, or an entity is disposed of inside a reporting date range | Consolidation follows the dates recorded on the scope rule rather than the boundaries of the fiscal year: the Balance Sheet of an entering entity is consolidated from its consolidation-from date and only its post-entry result reaches the group result, while a disposed entity contributes its result up to the disposal date and no balance thereafter. For an entity acquired from a third party, pre-acquisition reserves are carried at the historical rate as of the acquisition date rather than at the reporting date's closing rate. Each date is held on the rule set so the split is reproducible from configuration rather than re-derived per run, and the group Currency Translation Adjustment 3200 for the quarter ended 2025-03-31 stays at `$11,090.00 USD` regardless of an entity admitted for a later quarter |
| 5 | **Entity in a currency whose rounding increment is not 0.01** — an entity measured in a currency such as JPY, whose rounding increment is 1 and whose decimal places are therefore 0, enters a group presenting in USD at an increment of 0.01 | Precision is read from each currency record at translation time: the entity's own balances stay at the decimal places its functional currency declares, and the amount translated into USD is rounded to 2 decimal places at the USD rounding increment of 0.01. The rule set records the entity's functional-currency increment beside its scope row so a reviewer reads why a source amount carries no decimal places, the rounding difference arising on translation is presented in Currency Translation Adjustment 3200 rather than absorbed into Retained Earnings 3100, and no code path assumes 2 decimal places for an entity currency |

- [ ] **C-014 — Company isolation is respected rather than bypassed.** Reading the charts and balances of Global Holdings Inc., Global Europe SARL and Global Asia Pte Ltd together is an explicit, logged elevation rather than a suspension of record rules, and the mapping of one entity never exposes the ledger of another: Scenario 3 asserts that the mapping of Global Europe SARL leaves that of Global Asia Pte Ltd as it stands.

- [ ] **Rate-source authenticity, freshness and post-lock revision (CWE-345).** A well-formed, schema-valid response is not evidence that a rate is genuine, current or new, and a group position is only as trustworthy as the rate class behind it. ### Accounting Standards Compliance

- [ ] **IFRS 10 and US GAAP ASC 810 — consolidation scope, method and elimination.** Control determines the scope: Global Europe SARL and Global Asia Pte Ltd are wholly owned at 100.00% and fully consolidated, so the rule set measures a non-controlling interest of 0.00% for each and recognizes no goodwill, and the investment elimination is the subscribed capital and nothing else at `$256,000.00 USD`, rounded to 2 decimal places at the USD rounding increment of 0.01. ### Discovery versus Prescription

**Fixed by this story and not open to redesign:** the consolidation scope of three entities with full consolidation and an ownership percentage of 100.00% against each subsidiary; the non-controlling interest of 0.00% and the absence of any goodwill; the requirement that every in-scope account resolve to exactly one group taxonomy node; the rate class applied to each class of balance together with its rate-date basis; the treatment of opening retained earnings as carried forward rather than retranslated; the residual belonging to Currency Translation Adjustment 3200 while a monetary-balance retranslation belongs to Foreign Exchange Gain/Loss 7200; the three elimination pairs with their debit and credit accounts, their amounts and the Miscellaneous journal; every figure of the two worked translations, including the residuals of `$1,230.00 USD` and `$9,860.00 USD` and the group total of `$11,090.00 USD`; the refusals in Scenarios 5 and 6; and the Definition of Done below, including the 80% coverage gate and demonstrability in the Odoo user interface, or over the JSON web-service surface C-023 governs under a dedicated named integration principal.

**Deferred to agent discovery:** where the rule set is stored, and the mechanism by which a version is recorded and an approval attached — **not** whether an author may approve its own version, which RATE-001 fixes as a refusal; whether the mapping rides on shared account records, a dedicated mapping model or report-line definitions sourced from a code prefix; how a mid-year statutory account is treated pending assignment; the resolution mechanism for a rate class given the structure STORY-001-06-01 settles; how the cross-company read is authorized and logged; and the field-level and view-level design of every model this story touches. **Not deferred, because the platform or a canonical register decides it:** that the group relationship is held on a consolidation-scope record rather than on `res.company.parent_id`; that this story introduces no account code, because a code is claimed in the FEATURE-001-01 §7.4 registry and the Epic's canonical chart before any criterion cites it; and that the entity names, functional currencies, ownership percentages and consolidation dates are those of the Epic's canonical legal-entity register.

## Estimation

| Dimension | Rating | Justification |
|-----------|--------|---------------|
| **Effort** | Medium-High | Four interlocking rule classes in one artifact: 1 consolidation scope holding 3 entities with a method and an ownership percentage against each of 2 subsidiaries, 2 entity charts mapped account by account onto the group taxonomy, 5 rate-selection classes across 3 rate-date bases plus the carried-forward and intercompany clauses, and 3 registered elimination pairs. On top of the build sit two translation reconciliations that must close to `0.00 USD` and three refusal guards — an unmapped account, an unresolvable rate class and an amendment offered against a locked period |
| **Complexity** | High | The arithmetic is where the complexity sits, not the configuration surface. A translated position closes only when every class of balance is taken at its own rate and rate date: the same `€850,000.00 EUR` reaches `$922,250.00 USD` at the closing rate while the capital inside it is held at `$110,000.00 USD` at a rate six years older, the opening reserve is not retranslated at all, and the intercompany leg is translated at the rate that makes the trading elimination net to `$0.00 USD`. Getting the residual to land at `$1,230.00 USD` for Global Europe SARL and `$9,860.00 USD` for Global Asia Pte Ltd — rather than at a plug in Retained Earnings 3100 — is what the rule set has to make reproducible, and the rounding has to happen once at the presentation currency's increment rather than per line |
| **Uncertainty** | Medium | The unknowns are named rather than open: where the rule set is stored and versioned, whether the mapping rides on shared account records or a model of its own, and how a mid-year statutory account is treated pending assignment. The rate structure is settled by STORY-001-06-01 and consumed here. Two programme decisions sit above the story — DEC-001 for the platform version and DEC-002 for the edition source — and neither changes the rule **content**, which is why the policy is authorable now; DEC-002 changes only where the rules are expressed |
| **Story Points** | **8** | Fibonacci scale (1, 2, 3, 5, 8, 13) |

**Why 8 and not 5.** STORY-001-06-01 is a 5: a countable configuration surface with one translated total to prove. This story carries four rule classes that have to agree with each other — a mapping that resolves every account, a rate class per balance class across three date bases, a scope that decides which entities and which periods are in, and an elimination registry whose every rule must be specified to balance — and it has to close two entity reconciliations to the cent against the sub-ledger, with the residual landing in Currency Translation Adjustment 3200 rather than anywhere else. The verification surface is wider than the build: seven acceptance tests, the numeric assertions C-009 names, and the six hostile-input cases C-022 requires of this story on the rate-feed path.

**Why 8 and not 13.** Nothing in the story waits on an unanswered question outside it, no data migration is involved, no report is rendered and no journal entry is posted by it — the entries belong to STORY-001-06-04 and the statements to STORY-001-06-05. The entities, the rates, the account codes and the taxonomy are all supplied by predecessors and consumed unchanged, so the story defines policy over given data rather than creating the data.

## Notes

### Business Context

Consolidation in this organization is re-derived every period because the policy behind it is not written down anywhere the system can read. Nothing records which rate translates which class of balance, so the same euro balance reaches a different USD figure depending on who runs the workbook; nothing records how a local statutory account reaches a group line, so an account added in one entity quietly falls outside the group statements; and nothing records which intercompany pairs are eliminated, so a balance survives into the group position by omission rather than by decision. This story is the smallest change that turns those three silences into one governed artifact, and it is what allows the two stories after it to assert amounts at all: an elimination needs to know which group line an amount lands on, and a consolidated statement needs to know which rate produced the figure it presents.

### Why the Four Rule Classes Stay in One Story

Splitting the rule set would produce stories with no accounting proof of their own. A translation policy separated from the mapping has no group line to translate onto; a mapping separated from the scope has no entity set to map; an elimination registry separated from either has no amount basis and no group account to name. The four classes are verifiable only against each other — the residual of `$1,230.00 USD` lands in Currency Translation Adjustment 3200 only because the mapping puts it there and the rate classes produce it — which is why the Epic's decomposition keeps CAP-003 as one story inside a five-story feature.

### Reconciliation With the Canonical Registers

An earlier authoring pass of this folder read Global Asia Pte Ltd as partly owned, with a minority holding presented as a separate component of group equity, which would have required an equity account for that holding and a different investment-elimination arithmetic. That reading is **superseded** by the Epic's canonical legal-entity register ([Appendix E.4](../../EPIC-001-enterprise-accounting-odoo.md#e4-canonical-legal-entity-register)), which records every subsidiary as wholly owned at 100.00% and states that no goodwill and no non-controlling interest arise, and by [§8.1](../../EPIC-001-enterprise-accounting-odoo.md#81-explicitly-excluded-items), which places non-controlling-interest allocation outside the Epic's scope. The register's precedence rule is explicit — on any conflict between a ticket and the appendix, the appendix governs — so this story consumes the register unchanged: 100.00% ownership against each subsidiary, a non-controlling interest of 0.00%, an investment elimination of `$256,000.00 USD` that is the subscribed capital and nothing else, and **no new account code**. The consequence is recorded rather than hidden: were a partly owned entity admitted to the register later, the equity code for its non-controlling interest would be claimed in the [FEATURE-001-01 §7.4 Group Chart-of-Accounts Extension Registry](../FEATURE-001-01-chart-of-accounts-fiscal-year.md#74-group-chart-of-accounts-extension-registry) and added to Appendix E.2 in the same change, before any criterion cited it.

### Open Questions for Refinement

- Whether a local statutory account added mid-year inherits the group node of the closest parent account in its code range, as the taxonomy story does for a late-loaded account, or is held unmapped until the Group Controller assigns it — the answer decides whether Scenario 5 refuses a save or resolves it, and it is settled with the Chief Accountant before the build.
- Which entity is treated as the source of a rate when the group ever presents in a currency no entity uses as its functional currency, since the historical rate class is drawn from an incorporation date that then belongs to no presentation currency.
- Whether the group wants the intercompany translation clause stated as a policy of this rule set or inherited from the transfer-pricing convention that sets the charge, which decides where a change to it is approved.
- How a rule set is retired: whether a superseded version stays readable for the periods it produced, which the reproducibility requirement of Edge Case 2 implies, and for how long the External Auditor expects to read it.
